# 实验二：Linux 指令与内核模块编程 - 设计方案

## 一、项目概述

### 1.1 基本信息

| 项目 | 内容 |
|------|------|
| 赛题编号 | proj54 - OpenEuler 内核 Step by Step |
| 实验名称 | 实验二：基本 Linux 指令使用和内核模块编程 |
| 技术赛道 | 操作系统功能挑战赛道 |
| 开发环境 | openEuler 24.03 LTS (内核 6.6+) |
| 开发工具 | GCC, Make, kernel-devel |

### 1.2 功能目标

本实验分为两部分：

1. **基本 Linux 指令使用**：掌握用户管理、文件管理、系统管理等常用命令
2. **内核模块编程**：通过三个递进的 Checkpoint，掌握内核模块开发全流程

核心功能：
- 实现可加载/卸载的 Linux 内核模块
- 支持模块参数传递（设备名称、默认电压）
- 实现字符设备驱动，支持用户态读写电力数据
- 模拟电力设备监控场景，实现电压、电流、功率的读取与计算

### 1.3 技术栈选型及理由

| 技术选型 | 理由 |
|---------|------|
| **C 语言** | Linux 内核原生开发语言，性能最优，所有内核 API 均为 C 接口 |
| **misc 设备框架** | 相比传统字符设备注册（register_chrdev），misc 设备注册更简洁，自动分配主设备号（10），适合简单设备驱动 |
| **module_param 宏** | 内核标准参数传递机制，支持参数在 `/sys/module/` 下持久化，便于运行时查询 |
| **mutex 互斥锁** | 保护共享数据（电压、电流、功率），防止并发读写导致数据不一致 |
| **copy_to_user / copy_from_user** | 内核空间与用户空间数据拷贝的标准接口，确保内存安全 |

## 三、关键数据结构

### 3.1 电力数据结构

```c
/**
 * struct power_data - 电力设备数据结构
 * @voltage:  电压值，单位伏特(V)
 * @current:  电流值，单位安培(A)
 * @power:    功率值，单位瓦特(W)，由 voltage * current 计算
 *
 * 该结构体存储模拟电力设备的实时数据，通过互斥锁保护。
 */
struct power_data {
    int voltage;    /* 电压 (V) */
    int current;    /* 电流 (A) */
    int power;      /* 功率 (W) = voltage * current */
};

/* 初始值：220V × 10A = 2200W */
static struct power_data dev_data = {
    .voltage = 220,
    .current = 10,
    .power = 2200,
};
```

### 3.2 模块参数

```c
/* 设备名称参数，可通过 insmod 传入 */
static char *dev_name = "power_sensor";
module_param(dev_name, charp, 0644);
MODULE_PARM_DESC(dev_name, "Device name (default: power_sensor)");

/* 默认电压参数，可通过 insmod 传入 */
static int default_voltage = 220;
module_param(default_voltage, int, 0644);
MODULE_PARM_DESC(default_voltage, "Default voltage in volts (default: 220)");
```

**参数权限说明**：
- `0644`：表示参数在 `/sys/module/<模块名>/parameters/` 下可读可写
- `charp`：字符串指针类型
- `int`：整型类型

### 3.3 文件操作结构

```c
/**
 * struct file_operations - 字符设备文件操作
 *
 * 定义设备文件 /dev/power_device 支持的操作：
 * - .owner: 模块所有权，防止模块在使用时被卸载
 * - .read:  读取电力数据（电压、电流、功率）
 * - .write: 设置电压和电流，自动计算功率
 */
static const struct file_operations power_fops = {
    .owner = THIS_MODULE,
    .read  = power_read,
    .write = power_write,
};
```

### 3.4 misc 设备结构

```c
/**
 * struct miscdevice - 杂项设备结构
 *
 * 使用 misc 设备框架简化字符设备注册：
 * - .minor: MISC_DYNAMIC_MINOR 表示动态分配次设备号
 * - .name:  设备文件名，将创建为 /dev/power_device
 * - .fops:  文件操作接口
 * - .mode:  设备文件权限 0666（所有用户可读写）
 */
static struct miscdevice power_misc = {
    .minor = MISC_DYNAMIC_MINOR,
    .name = "power_device",
    .fops = &power_fops,
    .mode = 0666,
};
```

## 四、核心函数实现说明

### 4.1 模块初始化函数 (power_init)

```c
/**
 * power_init - 模块加载函数
 *
 * 功能：
 * 1. 打印加载日志
 * 2. 打印模块参数值
 * 3. 注册 misc 设备，创建 /dev/power_device
 *
 * 返回值：
 * - 0: 成功
 * - 负数: 失败（misc_register 失败）
 */
static int __init power_init(void)
{
    int ret;

    printk(KERN_INFO "Power Device Module Loaded\n");
    printk(KERN_INFO "Device name: %s, default voltage: %d V\n",
           dev_name, default_voltage);

    /* 注册 misc 设备 */
    ret = misc_register(&power_misc);
    if (ret) {
        printk(KERN_ERR "Failed to register misc device: %d\n", ret);
        return ret;
    }

    printk(KERN_INFO "Device file: /dev/%s created\n", power_misc.name);
    return 0;
}
```

**关键点**：
- `__init` 宏：标记该函数仅在模块加载时调用，加载后内存可回收
- `misc_register()`：自动分配设备号，创建设备文件
- 错误处理：注册失败时返回错误码，阻止模块加载

### 4.2 模块卸载函数 (power_exit)

```c
/**
 * power_exit - 模块卸载函数
 *
 * 功能：
 * 1. 注销 misc 设备
 * 2. 打印卸载日志
 *
 * 注意：卸载后 /dev/power_device 自动删除
 */
static void __exit power_exit(void)
{
    misc_deregister(&power_misc);
    printk(KERN_INFO "Power Device Module Unloaded\n");
}
```

**关键点**：
- `__exit` 宏：标记该函数仅在模块卸载时调用
- `misc_deregister()`：注销设备，释放设备号

### 4.3 读取函数 (power_read)

```c
/**
 * power_read - 读取电力数据
 * @file:  文件结构指针
 * @buf:   用户空间缓冲区
 * @len:   缓冲区长度
 * @off:   文件偏移量
 *
 * 功能：
 * 1. 检查参数有效性
 * 2. 加锁保护共享数据
 * 3. 格式化输出：Voltage: X V\nCurrent: X A\nPower: X W\n
 * 4. 拷贝数据到用户空间
 * 5. 解锁并返回实际字节数
 *
 * 返回值：
 * - 正数: 实际读取的字节数
 * - 0: EOF（偏移量已到末尾）
 * - -EINVAL: 参数无效
 * - -EFAULT: 拷贝失败
 */
static ssize_t power_read(struct file *file, char __user *buf,
                          size_t len, loff_t *off)
{
    char kbuf[64];
    int ret;

    /* 参数检查 */
    if (buf == NULL || len < 64)
        return -EINVAL;

    /* 偏移量检查：防止重复读取 */
    if (*off > 0)
        return 0;

    mutex_lock(&data_mutex);

    /* 格式化输出 */
    ret = snprintf(kbuf, sizeof(kbuf),
                   "Voltage: %d V\nCurrent: %d A\nPower: %d W\n",
                   dev_data.voltage, dev_data.current, dev_data.power);

    if (ret < 0 || ret >= sizeof(kbuf)) {
        mutex_unlock(&data_mutex);
        return -EIO;
    }

    /* 拷贝到用户空间 */
    if (copy_to_user(buf, kbuf, ret)) {
        mutex_unlock(&data_mutex);
        return -EFAULT;
    }

    mutex_unlock(&data_mutex);

    *off += ret;  /* 更新偏移量 */
    return ret;
}
```

**关键技术点**：
1. **偏移量检查**：`*off > 0` 防止 `cat` 命令重复读取
2. **互斥锁保护**：`mutex_lock/unlock` 防止并发读写
3. **内核空间到用户空间拷贝**：`copy_to_user()` 确保内存安全
4. **缓冲区大小检查**：防止用户态缓冲区溢出

### 4.4 写入函数 (power_write)

```c
/**
 * power_write - 设置电力参数
 * @file:  文件结构指针
 * @buf:   用户空间缓冲区
 * @len:   数据长度
 * @off:   文件偏移量
 *
 * 功能：
 * 1. 从用户空间获取输入数据
 * 2. 解析格式：<voltage> <current>
 * 3. 加锁更新数据并计算功率
 * 4. 解锁并返回写入字节数
 *
 * 输入格式示例：
 *   echo "380 15" > /dev/power_device
 *
 * 返回值：
 * - len: 成功写入的字节数
 * - -EINVAL: 参数无效或格式错误
 * - -EFAULT: 拷贝失败
 */
static ssize_t power_write(struct file *file, const char __user *buf,
                           size_t len, loff_t *off)
{
    char kbuf[32];
    int voltage, current;

    /* 参数检查 */
    if (buf == NULL || len > sizeof(kbuf))
        return -EINVAL;

    /* 从用户空间拷贝数据 */
    if (copy_from_user(kbuf, buf, len))
        return -EFAULT;

    kbuf[len] = '\0';

    /* 解析输入：两个整数 */
    if (sscanf(kbuf, "%d %d", &voltage, &current) != 2) {
        printk(KERN_WARNING "Invalid input format: %s\n", kbuf);
        return -EINVAL;
    }

    mutex_lock(&data_mutex);

    /* 更新数据 */
    dev_data.voltage = voltage;
    dev_data.current = current;
    dev_data.power = voltage * current;  /* 自动计算功率 */

    printk(KERN_INFO "Power device updated: V=%d, I=%d, P=%d\n",
           voltage, current, dev_data.power);

    mutex_unlock(&data_mutex);

    return len;
}
```

**关键技术点**：
1. **用户空间到内核空间拷贝**：`copy_from_user()`
2. **字符串解析**：`sscanf()` 解析 `"电压 电流"` 格式
3. **自动计算功率**：`power = voltage * current`
4. **日志记录**：`printk()` 记录每次修改，便于调试

## 五、开发过程中遇到的问题与解决方法

### 问题 1：编译时找不到内核头文件

**问题描述**：
```bash
fatal error: linux/module.h: No such file or directory
```

**原因分析**：
- 未安装 `kernel-devel` 包
- 内核版本与 `kernel-devel` 版本不匹配

**解决方案**：
```bash
# 安装内核开发包
sudo dnf install -y kernel-devel gcc make

# 检查内核版本
uname -r

# 确保 kernel-devel 版本一致
rpm -qa | grep kernel-devel
```

### 问题 2：模块加载失败（权限不足）

**问题描述**：
```bash
insmod: ERROR: could not insert module power_device_cp1.ko: Permission denied
```

**原因分析**：
- 加载内核模块需要 root 权限

**解决方案**：
```bash
# 使用 sudo 加载模块
sudo insmod power_device_cp1.ko

# 或切换到 root 用户
su -
insmod power_device_cp1.ko
```

### 问题 3：模块加载后看不到输出日志

**问题描述**：
```bash
sudo insmod power_device_cp1.ko
# 没有看到 "Power Device Module Loaded" 输出
```

**原因分析**：
- `printk` 输出到内核日志缓冲区，不在终端显示
- 需要使用 `dmesg` 命令查看

**解决方案**：
```bash
# 查看最新 20 行内核日志
dmesg | tail -20

# 或实时查看内核日志
journalctl -k -f

# 或设置控制台日志级别
dmesg -n 8  # 打印所有级别 >= 8 的消息
```

### 问题 4：设备文件权限不足

**问题描述**：
```bash
cat /dev/power_device
cat: /dev/power_device: Permission denied
```

**原因分析**：
- 设备文件默认权限可能限制普通用户访问

**解决方案**：

**方法 1**：临时修改权限
```bash
sudo chmod 666 /dev/power_device
```

**方法 2**：在代码中设置设备权限
```c
static struct miscdevice power_misc = {
    .minor = MISC_DYNAMIC_MINOR,
    .name = "power_device",
    .fops = &power_fops,
    .mode = 0666,  /* 所有用户可读写 */
};
```

**问题描述**：

### 问题 6：write 操作无法正确解析输入

**问题描述**：
```bash
echo "380 15" | sudo tee /dev/power_device
# dmesg 显示 "Invalid input format"
```

**原因分析**：
- `echo` 命令可能添加了换行符或其他不可见字符
- `sscanf` 解析失败

**解决方案**：

**方法 1**：在代码中增加容错处理
```c
/* 去除尾部换行符 */
if (kbuf[len-1] == '\n')
    kbuf[len-1] = '\0';
```

**方法 2**：使用 `echo -n` 去除换行符
```bash
echo -n "380 15" | sudo tee /dev/power_device
```

## 六、创新点与技术优势

### 6.1 与传统字符设备驱动对比

| 对比项 | 传统字符设备 (register_chrdev) | misc 设备框架 |
|--------|-------------------------------|---------------|
| **代码复杂度** | 高（需手动分配设备号） | 低（自动分配） |
| **设备号管理** | 需要手动申请主设备号 | 固定主设备号 10 |
| **设备文件创建** | 需手动创建（mknod） | 自动创建 |
| **适用场景** | 复杂设备、多设备实例 | 简单设备、单实例 |

**本实验选择 misc 设备的理由**：
- 电力设备驱动功能简单，仅需读写操作
- 单设备实例（一个 `/dev/power_device`）
- 代码简洁，适合教学演示

### 6.2 并发安全设计

```c
/* 使用互斥锁保护共享数据 */
static DEFINE_MUTEX(data_mutex);

/* 读操作 */
mutex_lock(&data_mutex);
// 读取数据
mutex_unlock(&data_mutex);

/* 写操作 */
mutex_lock(&data_mutex);
// 更新数据
mutex_unlock(&data_mutex);
```

**优势**：
- 防止多进程同时读写导致数据不一致
- 相比自旋锁，互斥锁在等待时可休眠，不浪费 CPU

### 6.3 用户态交互友好性

| 操作 | 命令 | 输出示例 |
|------|------|----------|
| 读取数据 | `cat /dev/power_device` | Voltage: 220 V<br>Current: 10 A<br>Power: 2200 W |
