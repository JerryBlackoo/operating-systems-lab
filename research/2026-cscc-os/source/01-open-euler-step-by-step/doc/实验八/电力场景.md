# 实验八 · 电力场景深度解读

## 场景背景

本实验模拟 **电力系统网络的安全防护与高性能数据包处理**。电力关键基础设施（电网调度系统、变电站自动化系统）对网络通信的实时性和安全性有极高要求。本实验通过三阶段递进（Socket → Netfilter → XDP），让学生从用户态到内核态再到网卡驱动层，完整体验电力系统网络防护的不同技术层次。

---

## 三阶段技术与电力场景对应

| 阶段 | 技术方案 | 电力场景应用 | 性能层级 |
|------|---------|-------------|---------|
| Phase 1 | UDP Socket | 电力采集数据上传（用户态） | ~1M PPS |
| Phase 2 | Netfilter 钩子 | 电力协议防火墙（内核态） | ~3M PPS |
| Phase 3 | XDP (eBPF) | 高性能电力协议过滤（网卡层） | ~8M+ PPS |

---

## 电力协议背景知识

### 1. IEC 60870-5-104（电力远动协议）

电力调度系统与变电站之间最常用的远动通信协议：

- **传输层**：TCP
- **标准端口**：2404
- **特点**：长连接、实时性要求高、支持遥测/遥信/遥控/遥调
- **数据流向**：变电站 → 调度中心（上行），调度中心 → 变电站（下行）

### 2. IEC 61850（智能变电站通信标准）

新一代智能变电站的核心通信标准：

- **传输层**：TCP/IP + MMS + GOOSE + SV
- **标准端口**：102（MMS）
- **特点**：面向对象建模、支持发布/订阅模式
- **应用场景**：站内设备间通信、联锁保护

### 3. DL/T 634.5-104（中国电力行业远动标准）

中国版 IEC 104 标准，在国网和南网广泛使用：

- **传输层**：TCP
- **标准端口**：2404
- **特点**：基于 IEC 60870-5-104，增加中国电力行业特性

### 4. Modbus TCP（工业设备通信）

电力二次设备常用的工业通信协议：

- **传输层**：TCP
- **标准端口**：502
- **应用场景**：智能开关柜、UPS、柴油发电机等设备监控

## 三阶段电力场景实现

### Phase 1: 电力数据 UDP 传输

模拟变电站采集终端通过 UDP 上传电力数据：

```c
// 电力数据包格式
struct power_packet {
    uint32_t device_id;     // 设备 ID
    uint16_t voltage;       // 电压 (×10, 如 2205 = 220.5V)
    uint16_t current;       // 电流 (×10, 如 102 = 10.2A)
    uint32_t power;         // 功率 (W)
    int16_t temperature;    // 温度 (×10, 如 453 = 45.3℃)
    uint64_t timestamp;     // 时间戳
};
```

**电力场景特点**：
- 采集频率高（毫秒级）
- 数据量适中（单包 32-64 字节）
- 实时性要求高（延迟 < 100ms）
- UDP 适合：无需重传、允许少量丢包

### Phase 2: 电力协议防火墙（Netfilter）

在内核协议栈层实现电力协议端口过滤：

```c
// 拦截电力协议端口的数据包
static unsigned int power_nf_hook(void *priv,
                                  struct sk_buff *skb,
                                  const struct nf_hook_state *state)
{
    struct iphdr *iph;
    struct udphdr *udph;

    // 仅处理 UDP 包
    if (ip_hdr(skb)->protocol != IPPROTO_UDP)
        return NF_ACCEPT;

    udph = udp_hdr(skb);

    // 拦截电力协议端口（40000 = 模拟端口，2404 = IEC 104）
    if (ntohs(udph->dest) == 40000 ||
        ntohs(udph->dest) == 2404) {
        printk(KERN_INFO "Power protocol packet: port %d\n",
               ntohs(udph->dest));
        // 可选: 执行深度包检测
        return NF_ACCEPT;  // 或 NF_DROP 拒绝
    }

    return NF_ACCEPT;
}
```

**电力场景应用**：
- 拦截非授权端口的电力协议数据
- 监控异常流量（如非调度主机访问 2404 端口）
- 实现简单防火墙规则

### Phase 3: 高性能电力协议过滤（XDP）

在网卡驱动层实现线速过滤：

```c
// XDP 程序：在网卡层过滤电力协议
SEC("xdp")
int xdp_power_filter(struct xdp_md *ctx)
{
    void *data_end = (void *)(long)ctx->data_end;
    void *data = (void *)(long)ctx->data;

    struct ethhdr *eth = data;
    if ((void *)(eth + 1) > data_end)
        return XDP_DROP;

    // 仅处理 IP 包
    if (eth->h_proto != htons(ETH_P_IP))
        return XDP_PASS;

    struct iphdr *iph = (void *)(eth + 1);
    if ((void *)(iph + 1) > data_end)
        return XDP_DROP;

    // 仅处理 UDP 包
    if (iph->protocol != IPPROTO_UDP)
        return XDP_PASS;

    struct udphdr *udph = (void *)(iph + 1);
    if ((void *)(udph + 1) > data_end)
        return XDP_DROP;

    // 电力协议端口白名单
    __u16 port = ntohs(udph->dest);
    if (port == 40000 ||    // 模拟电力协议
        port == 2404  ||    // IEC 104
        port == 502   ||    // Modbus TCP
        port == 102) {      // IEC 61850 MMS
        return XDP_PASS;    // 放行电力协议
    }

    // 可选：丢弃非电力协议流量
    // return XDP_DROP;

    return XDP_PASS;
}
```

**电力场景特点**：
- 线速处理（~8M+ PPS）
- 零拷贝，CPU 占用低
- 适合 DDoS 防护场景
- 可实现协议白名单/黑名单

## 性能对比与场景选择

| 场景 | 推荐技术 | 理由 |
|------|---------|------|
| 电力数据采集上传 | UDP Socket | 开发简单，满足实时性 |
| 站内协议监控 | Netfilter | 可深度检测，规则灵活 |
| DDoS 防护 | XDP | 线速过滤，CPU 占用低 |
| 协议白名单 | XDP + Netfilter 组合 | XDP 快速过滤，Netfilter 深度检测 |

## 实际应用案例

### 案例1：智能变电站网络防护

变电站二次系统网络需要：

- **外网隔离**：XDP 丢弃所有非电力协议流量
- **协议监控**：Netfilter 记录 IEC 104 流量
- **数据采集**：Socket 接收采集数据

### 案例2：调度中心 DDoS 防护

调度中心面临 DDoS 攻击时：

- **XDP 层**：丢弃 SYN Flood、UDP Flood
- **Netfilter 层**：限速 IEC 104 连接
- **应用层**：验证协议合法性

### 案例3：配电自动化通信

配电终端与主站通信：

- **正常流量**：IEC 104（TCP 2404）
- **异常检测**：Netfilter 监控异常端口
- **应急隔离**：XDP 快速切断异常流量

## 实验与实际开发的差异

| 实验模拟 | 实际开发 | 差异说明 |
|---------|---------|---------|
| 模拟端口 40000 | IEC 104 端口 2404 | 实际使用标准端口 |
| 简单端口过滤 | 深度包检测（DPI） | 实际需要解析协议字段 |
| 单机测试 | 分布式部署 | 实际需要多节点协同 |
| 无加密 | TLS/IPsec 加密 | 实际需要加密通信 |
| 无认证 | 证书+数字签名 | 实际需要强认证 |

## 扩展思考与挑战

### 1. 实现协议深度检测

不仅过滤端口，还要解析 IEC 104 协议字段：

```c
// 解析 IEC 104 APDU
struct apdu {
    uint8_t start;      // 起始字节 0x68
    uint8_t length;     // APDU 长度
    // ... 后续字段
};
```

### 2. 实现流量限速

对电力协议流量进行限速，防止异常流量冲击：

```c
// 使用 token bucket 算法
if (token_count < packet_size) {
    return XDP_DROP;  // 限速丢弃
}
```

### 3. 实现黑白名单

基于源 IP 的黑白名单过滤：

```c
// 使用 BPF map 存储黑名单 IP
struct bpf_map_def SEC("maps") blacklist = {
    .type = BPF_MAP_TYPE_HASH,
    .key_size = sizeof(uint32_t),    // IP 地址
    .value_size = sizeof(uint8_t),   // 标记
    .max_entries = 1024,
};
```
