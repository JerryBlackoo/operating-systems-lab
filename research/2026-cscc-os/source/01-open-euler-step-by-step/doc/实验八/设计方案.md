# 实验八：网络管理 - 设计方案

## 一、项目概述

### 1.1 基本信息

| 项目 | 内容 |
|------|------|
| 赛题编号 | proj54 - OpenEuler 内核 Step by Step |
| 实验名称 | 实验八：网络管理 |
| 技术赛道 | 操作系统功能挑战赛道 |
| 开发环境 | openEuler 24.03 LTS (内核 6.6+) |
| 开发工具 | GCC, Make, iproute2, bpftool |

### 1.2 功能目标

本实验采用**三阶段递进式**实现网络数据包拦截与过滤：

| 阶段 | 技术方案 | 功能目标 | 学习目标 |
|------|---------|----------|----------|
| **Phase 1** | Socket 编程 | UDP 服务器回显功能 | 掌握用户态网络编程基础 |
| **Phase 2** | Netfilter 内核模块 | 拦截 UDP 40000 端口数据包 | 理解传统内核网络栈拦截 |
| **Phase 3** | XDP (eBPF) | 高性能数据包过滤 | 掌握现代内核旁路技术 |

### 1.3 技术栈选型及理由

| 技术选型 | 理由 |
|---------|------|
| **UDP Socket** | 无连接、简单，适合教学演示；实验指导书要求监听 40000 端口 |
| **Netfilter** | Linux 内核标准网络栈框架，功能强大、文档丰富 |
| **XDP (eXpress Data Path)** | 内核态快速路径，性能远超 Netfilter，现代高性能网络技术 |
| **eBPF** | 安全的内核态编程，无需编译内核模块，适合生产环境 |

### 2.2 Phase 1: UDP Socket 服务器

#### 架构图

```
┌──────────────────────────────────────────────────────────┐
│                      UDP 服务器                           │
│                                                          │
│  ┌────────────────────────────────────────────────────┐ │
│  │  socket(AF_INET, SOCK_DGRAM, 0)                    │ │
│  └─────────────────────┬──────────────────────────────┘ │
│                        │                                │
│  ┌─────────────────────┴──────────────────────────────┐ │
│  │  bind(sock, (struct sockaddr*)&addr, sizeof(addr))│ │
│  │  addr.sin_port = htons(40000)                     │ │
│  └─────────────────────┬──────────────────────────────┘ │
│                        │                                │
│  ┌─────────────────────┴──────────────────────────────┐ │
│  │  while(1) {                                        │ │
│  │      recvfrom(sock, buf, LEN, 0, &client, &len);  │ │
│  │      sendto(sock, buf, LEN, 0, &client, len);     │ │
│  │  }                                                 │ │
│  └────────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────┘
```

#### 核心数据结构

```c
/**
 * UDP 服务器地址结构
 */
struct sockaddr_in server_addr = {
    .sin_family = AF_INET,
    .sin_port = htons(40000),           /* 监听端口 40000 */
    .sin_addr.s_addr = INADDR_ANY,      /* 监听所有网卡 */
};
```

#### 核心流程

```c
/**
 * UDP 回显服务器
 */
int main() {
    int sock = socket(AF_INET, SOCK_DGRAM, 0);

    /* 绑定端口 */
    bind(sock, (struct sockaddr*)&server_addr, sizeof(server_addr));

    printf("UDP Echo Server listening on port 40000\n");

    /* 循环处理客户端请求 */
    while (1) {
        struct sockaddr_in client_addr;
        socklen_t client_len = sizeof(client_addr);
        char buffer[1024];

        /* 接收数据 */
        int n = recvfrom(sock, buffer, sizeof(buffer), 0,
                         (struct sockaddr*)&client_addr, &client_len);

        /* 打印客户端信息 */
        printf("Received from %s:%d: %s\n",
               inet_ntoa(client_addr.sin_addr),
               ntohs(client_addr.sin_port),
               buffer);

        /* 回显数据 */
        sendto(sock, buffer, n, 0,
               (struct sockaddr*)&client_addr, client_len);
    }

    close(sock);
    return 0;
}
```

#### 核心数据结构

```c
/**
 * nf_hook_ops - Netfilter 钩子操作结构
 */
static struct nf_hook_ops nfho = {
    .hook     = hook_func,              /* 钩子函数 */
    .pf       = PF_INET,                /* 协议族：IPv4 */
    .hooknum  = NF_INET_PRE_ROUTING,    /* 钩子点：入站路由前 */
    .priority = NF_IP_PRI_FIRST,        /* 优先级：最高 */
};
```

#### 钩子函数实现

```c
/**
 * hook_func - Netfilter 钩子函数
 * @priv:   私有数据
 * @skb:    socket buffer（数据包）
 * @state:  Netfilter 钩子状态
 *
 * 功能：
 * 1. 检查是否为 UDP 协议
 * 2. 检查目标端口是否为 40000
 * 3. 拦截并记录日志
 *
 * 返回值：
 * - NF_DROP:   丢弃数据包
 * - NF_ACCEPT: 接受数据包
 */
static unsigned int hook_func(void *priv,
                              struct sk_buff *skb,
                              const struct nf_hook_state *state)
{
    struct iphdr *iph;
    struct udphdr *udph;

    /* 获取 IP 头 */
    iph = ip_hdr(skb);
    if (!iph || iph->protocol != IPPROTO_UDP)
        return NF_ACCEPT;

    /* 获取 UDP 头 */
    udph = udp_hdr(skb);
    if (!udph)
        return NF_ACCEPT;

    /* 检查目标端口 */
    if (ntohs(udph->dest) == 40000) {
        printk(KERN_INFO "Netfilter: Dropped UDP packet to port 40000\n");
        return NF_DROP;  /* 丢弃数据包 */
    }

    return NF_ACCEPT;
}
```

#### 模块注册

```c
static int __init netfilter_init(void)
{
    /* 注册 Netfilter 钩子 */
    return nf_register_net_hook(&init_net, &nfho);
}

static void __exit netfilter_exit(void)
{
    /* 注销钩子 */
    nf_unregister_net_hook(&init_net, &nfho);
}

module_init(netfilter_init);
module_exit(netfilter_exit);
MODULE_LICENSE("GPL");
```

### 2.4 Phase 3: XDP (eBPF) 高速数据包处理

#### XDP 在网络栈中的位置

```
┌─────────────────────────────────────────────────────────────┐
│                 XDP vs Netfilter 性能对比                   │
│                                                             │
│  ┌─────────────────────────────────────────────────────┐   │
│  │              传统路径 (Netfilter)                    │   │
│  │                                                     │   │
│  │  网卡 ──► 驱动 ──► skb分配 ──► 协议栈 ──► Socket    │   │
│  │            │           │           │               │   │
│  │            └───────────┴───────────┴─── 慢！       │   │
│  └─────────────────────────────────────────────────────┘   │
│                                                             │
│  ┌─────────────────────────────────────────────────────┐   │
│  │              XDP 快速路径                            │   │
│  │                                                     │   │
│  │  网卡 ──► XDP (driver层) ──► DROP (直接丢弃)       │   │
│  │            │                                         │   │
│  │            └─── 不经过协议栈，超快！                │   │
│  └─────────────────────────────────────────────────────┘   │
│                                                             │
│  XDP 程序执行时机：                                         │
│  - 在驱动层（skb 分配之前）                                 │
│  - 直接操作原始数据包                                       │
│  - 可实现每秒千万级 PPS                                     │
└─────────────────────────────────────────────────────────────┘
```

#### XDP 程序实现

```c
/**
 * xdp_filter.c - XDP 数据包过滤程序
 *
 * 编译命令：
 *   clang -O2 -target bpf -c xdp_filter.c -o xdp_filter.o
 *
 * 加载命令：
 *   ip link set dev lo xdp obj xdp_filter.o sec xdp
 */

#include <linux/bpf.h>
#include <linux/pkt_cls.h>
#include <bpf/bpf_helpers.h>
#include <linux/if_ether.h>
#include <linux/ip.h>
#include <linux/udp.h>

SEC("xdp")
int xdp_drop_port(struct xdp_md *ctx)
{
    void *data_end = (void *)(long)ctx->data_end;
    void *data     = (void *)(long)ctx->data;

    struct ethhdr *eth = data;
    struct iphdr *ip;
    struct udphdr *udp;

    /* 边界检查：确保可以读取以太网头 */
    if ((void *)(eth + 1) > data_end)
        return XDP_PASS;

    /* 仅处理 IPv4 */
    if (eth->h_proto != htons(ETH_P_IP))
        return XDP_PASS;

    ip = (void *)(eth + 1);

    /* 边界检查：确保可以读取 IP 头 */
    if ((void *)(ip + 1) > data_end)
        return XDP_PASS;

    /* 仅处理 UDP */
    if (ip->protocol != IPPROTO_UDP)
        return XDP_PASS;

    udp = (void *)(ip + 1);

    /* 边界检查：确保可以读取 UDP 头 */
    if ((void *)(udp + 1) > data_end)
        return XDP_PASS;

    /* 检查目标端口 */
    if (udp->dest == htons(40000)) {
        bpf_printk("XDP: Dropped UDP packet to port 40000\n");
        return XDP_DROP;  /* 丢弃数据包 */
    }

    return XDP_PASS;
}

char _license[] SEC("license") = "GPL";
```

#### XDP 程序加载与管理

```bash
# 编译 XDP 程序
clang -O2 -target bpf -c xdp_filter.c -o xdp_filter.o

# 加载 XDP 程序到网卡
ip link set dev lo xdp obj xdp_filter.o sec xdp

# 查看 XDP 状态
ip link show dev lo

# 卸载 XDP 程序
ip link set dev lo xdp off

# 查看 XDP 日志
cat /sys/kernel/debug/tracing/trace_pipe
```

## 三、技术对比分析

### 3.1 性能对比

| 对比项 | Socket (用户态) | Netfilter (内核态) | XDP (driver层) |
|--------|----------------|-------------------|----------------|
| **处理位置** | 应用层 | 协议栈 | 驱动层 |
| **数据包拷贝** | 多次（内核→用户） | 少量 | 0 次（零拷贝） |
| **理论性能** | ~1M PPS | ~2-5M PPS | ~10-40M PPS |
| **延迟** | 高（上下文切换） | 中等 | 极低 |
| **开发复杂度** | 低 | 中 | 高 |
| **灵活性** | 高 | 高 | 中（eBPF限制） |

### 3.2 适用场景

| 技术 | 适用场景 |
|------|---------|
| **Socket** | 应用层服务器、客户端通信 |
| **Netfilter** | 防火墙、NAT、端口转发 |
| **XDP** | DDoS 防护、负载均衡、高性能转发 |

## 四、开发过程中遇到的问题与解决方法

### 问题 1：Netfilter 模块加载失败

**问题描述**：
```bash
sudo insmod netfilter_hook.ko
insmod: ERROR: could not insert module netfilter_hook.ko: Invalid module format
```

**原因分析**：
- 内核版本与模块编译版本不匹配
- 缺少 `MODULE_LICENSE` 宏

**解决方案**：
```bash
# 检查内核版本
uname -r

# 确保 Makefile 中指定正确内核路径
make KERNELDIR=/lib/modules/$(uname -r)/build
```

---

### 问题 2：XDP 程序编译失败

**问题描述**：
```bash
clang: error: unknown target triple 'bpf'
```

**原因分析**：
- clang 版本过低，不支持 BPF target

**解决方案**：
```bash
# 安装最新 clang 和 llvm
sudo dnf install -y clang llvm

# 验证版本
clang --version  # 需要 >= 3.8
```

---

### 问题 3：XDP 程序无法加载到网卡

**问题描述**：
```bash
ip link set dev lo xdp obj xdp_filter.o sec xdp
RTNETLINK answers: Operation not supported
```

**原因分析**：
- 网卡驱动不支持 XDP
- 内核未启用 CONFIG_BPF

**解决方案**：
```bash
# 检查内核配置
grep CONFIG_BPF /boot/config-$(uname -r)

# 检查网卡是否支持 XDP
ethtool -i lo

# 尝试使用其他网卡（如 eth0）
ip link set dev eth0 xdp obj xdp_filter.o sec xdp
```

---

### 问题 4：XDP 日志无法查看

**问题描述**：
- 加载 XDP 后看不到 `bpf_printk` 输出

**原因分析**：
- eBPF 日志需要通过 trace_pipe 查看

**解决方案**：
```bash
# 实时查看 eBPF 日志
cat /sys/kernel/debug/tracing/trace_pipe

# 或使用 bpftool
bpftool prog tracelog
```

## 五、创新点与技术优势

### 5.1 三阶段递进式学习设计

| 阶段 | 学习目标 | 技术深度 |
|------|---------|---------|
| **Phase 1** | 掌握 Socket 网络编程基础 | 应用层 |
| **Phase 2** | 理解内核网络栈拦截原理 | 内核层 |
| **Phase 3** | 掌握现代高性能网络技术 | 驱动层 |

### 5.2 XDP 技术亮点

1. **零拷贝**：数据包不进入协议栈，直接在驱动层处理
2. **高性能**：可达 10M+ PPS（每秒千万级数据包）
3. **安全性**：eBPF 验证器确保程序安全，不会导致内核崩溃
4. **动态加载**：无需重启内核，运行时加载/卸载
