## 四、评测运行要求

1. 初赛评测使用 QEMU 虚拟环境。
2. 项目根目录必须包含 `Makefile`。
3. 评测会执行 `make all`。
4. `make all` 应生成 ELF 格式内核：`kernel-rv` 和 `kernel-la`。
5. 如系统需要辅助文件，可生成 `disk.img`；LoongArch 可使用 `disk-la.img`。磁盘镜像可选。
6. QEMU 会通过 `-drive file={fs}` 挂载 EXT4 文件系统镜像，其中包含预编译 ELF 可执行文件和测试脚本。
7. 测试脚本命名格式：`xxxxx_testcode.sh`。
8. OS 启动后需要主动扫描磁盘，依次运行测试点，并把结果输出到屏幕。
9. 评测系统根据屏幕输出评分。
10. 可按完成度跳过若干测试点，未运行测试点不计分。
11. 即使不直接运行脚本，也需按脚本格式输出测试点前后提示信息，例如 `#### OS COMP TEST GROUP START basic ####`，否则影响评分。
12. 测试点执行顺序与评分无关；多个测试点只能串行运行，不可并行。
13. 运行完所有测试点后应主动关机；评测机在检测 QEMU 退出或达到最长限制后打分。
14. 引用第三方工具/库应以源代码方式提交并随内核编译，不应直接提交二进制文件。
15. Clone 项目时会过滤隐藏文件/目录；若依赖 `.cargo` 等隐藏目录，可改名提交，构建时再改回。
16. 对评测机进行任何形式逆向工程视为作弊。

QEMU 版本：`9.2.1`。

评测镜像：`docker pull zhouzhouyi/os-contest:20260510`。

## 五、测试点总览

测试套件来自 `testsuits-for-oskernel` 的 `pre-2025` 分支。README 称包含 12 组测试题目：basic、busybox、lua、libctest、iozone、unixbench、iperf、libcbench、lmbench、netperf、cyclictest、LTP。

### 测试点脚本清单

| 组 | 脚本 | START/END 标识 | 主要内容 |
|---|---|---|---|
| basic | `scripts/basic/basic_testcode.sh` | basic | 进入 `basic` 目录执行 `run-all.sh`，覆盖基础 syscall/文件/进程类用例。 |
| busybox | `scripts/busybox/busybox_testcode.sh` | busybox | 逐行执行 `busybox_cmd.txt` 中 55 条 BusyBox 命令，检查返回值。 |
| cyclictest | `scripts/cyclictest/cyclictest_testcode.sh` | cyclictest | 无压力/有 hackbench 压力下运行 cyclictest，线程数 1 和 8。 |
| iozone | `scripts/iozone/iozone_testcode.sh` | iozone | 文件系统吞吐测试，覆盖 write/read、random-read、read-backwards、stride-read、fwrite/fread、pwrite/pread、pwritev/preadv。 |
| iperf | `scripts/iperf/iperf_testcode.sh` | iperf | 本机 `127.0.0.1:5001` 启动 iperf3 server，测试 UDP/TCP、parallel、reverse。 |
| libcbench | `scripts/libcbench/libcbench_testcode.sh` | libcbench | 运行 `./libc-bench`。 |
| libctest | `scripts/libctest/libctest_testcode.sh` | libctest | 运行 `run-static.sh` 与 `run-dynamic.sh`。 |
| lmbench | `scripts/lmbench/lmbench_testcode.sh` | lmbench | syscall、select、signal、pipe、fork/exec/shell、文件带宽、pagefault、mmap、fs latency、pipe/file/mmap bandwidth、context switch。 |
| ltp | `scripts/ltp/ltp_testcode.sh` | ltp | 遍历 `ltp/testcases/bin` 下所有文件并执行，输出每个 LTP CASE 的返回值。 |

1. 先保证内核能识别 EXT4 镜像并扫描根目录测试脚本。
2. 输出格式要严格包含每组 `#### OS COMP TEST GROUP START/END name ####`。
3. `make all` 产物必须稳定生成 `kernel-rv` 和 `kernel-la`。
4. 尽早支持基础 syscall、进程、文件系统、管道、时间、内存映射。
5. 性能组需要文件系统、网络、调度和上下文切换能力逐步补齐。
6. 网络相关测试使用 loopback：`127.0.0.1`。
7. 结束后主动关机，避免“评测时间过长”。
