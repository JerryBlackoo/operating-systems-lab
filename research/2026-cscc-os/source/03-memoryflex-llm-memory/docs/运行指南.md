# 项目运行指南（从零开始）

> 本文件仅保存在本地（未入库，与 `docs/工业级演进路线.md` 相同）。
> 所有命令在 `D:\proj59` 下用**你本机账户的 PowerShell** 运行
> （内存受限实验依赖工作集裁剪/页锁定，不要在受限沙箱里跑）。

## 0. 目录分工

- `scripts\`：全部实验与工具脚本
- `tools\llama.cpp\`：引擎源码（含我们的补丁；嵌套 `.git` 已改名 `.git_bak`）
- `models\`：GGUF 模型（不入库，需先下载）
- `results\`：全部实验数据
- `docs\`：报告、图表、仪表盘、运行指南
- `patches\llama-memory-scheduler.patch`：引擎补丁（已应用）

## 1. 环境准备

```powershell
# 自检 GPU/CUDA 编译器/VS2022/git/cmake/Python/磁盘
powershell -ExecutionPolicy Bypass -File scripts\setup_env.ps1

# 构建 llama.cpp（gitcode 镜像克隆；自动覆盖失效的 CUDA_PATH_V13_0；CMake+CUDA 编译）
powershell -ExecutionPolicy Bypass -File scripts\build_llamacpp.ps1

# 下载模型到 models\（hf-mirror，断点续传）
powershell -ExecutionPolicy Bypass -File scripts\download_models.ps1 -ModelId qwen2.5-1.5b
powershell -ExecutionPolicy Bypass -File scripts\download_models.ps1 -ModelId qwen2.5-3b
powershell -ExecutionPolicy Bypass -File scripts\download_models.ps1 -ModelId olmoe-1b-7b
```

说明：`setup_env.ps1` 逐项输出 OK/WARN；`build_llamacpp.ps1` 存在性判断用
`CMakeLists.txt`（兼容 `.git_bak`），且 clone 失败**不会删除已有目录**；
`download_models.ps1` 校验文件大小，失败可重跑续传。

## 2. 阶段 0：基线评测

```powershell
# 1.5B GPU 基线（全部层上 GPU）
powershell -ExecutionPolicy Bypass -File scripts\run_baseline.ps1 -ModelId qwen2.5-1.5b -GpuLayers 99
# 1.5B CPU 基线（-GpuLayers 0）
powershell -ExecutionPolicy Bypass -File scripts\run_baseline.ps1 -ModelId qwen2.5-1.5b -GpuLayers 0
```

干什么：调用 `measure_baseline.py`——启动一个 llama-server，发送 N 个流式聊天请求，
逐 token 计时，输出 TTFT/TPOT（P50/P95/P99）、解码吞吐、进程 RSS 峰值、显存峰值，
结果存 `results\*.json`（后续所有实验的"满内存基线"）。

## 3. 阶段 1：访存行为分析

```powershell
# GGUF 参数布局/每 token 访存/预取窗口/KV 容量（解析头部，不读权重）
python scripts\analyze_gguf.py --model models\qwen2.5-1.5b-instruct-q4_k_m.gguf

# 前缀缓存仿真：命中率 vs 容量 + 命中长度分布
python scripts\kv_prefix_sim.py --out-dir docs\figures

# mmap 按需加载 vs no-mmap 全量读入的 RSS/磁盘时间线
python scripts\mem_timeline.py --model models\qwen2.5-1.5b-instruct-q4_k_m.gguf --out-dir docs\figures

# 前缀命中收益实测：冷启动 vs 同前缀命中的 TTFT
python scripts\measure_prefix_benefit.py --model models\qwen2.5-1.5b-instruct-q4_k_m.gguf --out-dir docs\figures

# 生成阶段 1 学术图表（fig1-7）
python scripts\figures_phase1.py
```

MoE 专家激活轨迹（需要带追踪的 llama-server）：

```powershell
$env:LLAMA_MOE_TRACE='results\olmoe_moe_trace.bin'
# 启动 llama-server（CPU，ngl 0）发送一个请求后关闭
python scripts\analyze_moe_trace.py --trace results\olmoe_moe_trace.bin --out-dir docs\figures
```

`LLAMA_MOE_TRACE` 让引擎把每 token 每层的 router 概率写入二进制轨迹；
`analyze_moe_trace.py` 解析专家激活频次、层覆盖率、top-10 集中度、相邻 token 重叠率。

## 4. 阶段 2：虚拟内存、按需加载与换出

```powershell
# 内存预算扫描（40/60/80/100%）
python scripts\run_membudget.py --model models\qwen2.5-1.5b-instruct-q4_k_m.gguf --model-id 1.5b --model-mb 1111 --budgets 40,60,80,100 --requests 3 --max-tokens 32

# MoE 页级热点专家锁定（OLMoE）
python scripts\gen_locked_experts.py --stats docs\figures\moe_trace_stats.json --top-k 8 --out results\olmoe_hot_experts.txt
python scripts\run_membudget.py --model models\OLMoE-1B-7B-0125-Q4_K_M.gguf --model-id olmoe --model-mb 4212 --budgets 30 --lock-list results\olmoe_hot_experts.txt --n-expert 64

# 生成阶段 2 图表（fig8-12）
python scripts\figures_phase2.py
```

`run_membudget.py` 干什么：对每个预算百分比启动带 MemoryScheduler 的 llama-server，
引擎按 FlexInfer 算法平衡锁定（FFN 优先/逐层均匀），工作集裁剪实现"换出"；
测量锁定字节、常驻内存、缺页数、TTFT/TPOT、吞吐，输出 `results\membudget_*.json`。
参数：`--model-mb` 模型大小（1.5B=1111，3B=2099，OLMoE=4212）；`--kv-sweep` 加测
KV f16/q8 精度影响。

## 5. 阶段 3：异步预取

```powershell
# 40% 预算 + 预取窗口 k=8（扫 k=0/4/8/12/16 得窗口曲线）
python scripts\run_membudget.py --model models\qwen2.5-1.5b-instruct-q4_k_m.gguf --model-id 1.5b_k8 --model-mb 1111 --budgets 40 --prefetch-layers 8

# 生成阶段 3 图表（fig13-15）
python scripts\figures_phase3.py
```

干什么：引擎用常驻后台线程提前"触达"本 token 末尾 k 层的未锁定权重页，
把缺页移出计算关键路径；k=0 即阶段 2 的同步换出基线。

## 6. 阶段 4：LMETRIC 集群调度

```powershell
# 生成多轮对话负载（4 用户 × 15 轮，用户专属前缀，随机到达）
python scripts\gen_chat_trace.py --out results\trace_chat.jsonl --users 4 --turns 15

# 三策略对比（LB / LMETRIC / Linear，4 实例 60% 预算）
python scripts\router_lmetric.py --trace results\trace_chat.jsonl --model models\qwen2.5-1.5b-instruct-q4_k_m.gguf --model-mb 1111 --instances 4 --budget-pct 60 --concurrency 2 --policies lb,lmetric,linear

# 热点检测器验证
python scripts\gen_hotspot_trace.py --out results\trace_hotspot.jsonl
python scripts\router_lmetric.py --trace results\trace_chat.jsonl --model models\qwen2.5-1.5b-instruct-q4_k_m.gguf --model-mb 1111 --instances 4 --budget-pct 60 --concurrency 2 --policies lmetric --hotspot

# 生成阶段 4 图表（fig16-18）
python scripts\figures_phase4.py
```

`router_lmetric.py` 干什么：启动 4 个带内存预算的 llama-server（模拟边缘节点）+ Python
路由器，把 trace 流式派发；路由器实现 LMETRIC 指标工厂（排队 P-token + BS，提交加/
完成减），按 `P-token × BS` 选最小实例；`--hotspot` 同时跑"无检测器/有检测器"两组，
验证两阶段热点检测器（式 2 监控 → 2|M| 连续判定 → 过滤 M 回退负载均衡）。

## 7. 阶段 6：稳定性验证

```powershell
python scripts\run_stability.py --model models\qwen2.5-1.5b-instruct-q4_k_m.gguf --budget-pct 40 --prefetch-layers 8 --requests 16 --max-tokens 24
```

干什么：40% 预算 + 预取 8 下连续处理 16 轮请求，每秒采样 RSS/线程数/缺页，
验证长跑无崩溃、无内存泄漏（RSS 增长≈0）、线程稳定，输出 `results\stability.json`。

## 8. 阶段 5：评测汇总与仪表盘

```powershell
# 汇总全部实验为统一指标表
python scripts\aggregate_metrics.py

# 集群关键对比重复 3 次（mean±std）
python scripts\run_eval_rep.py --trace results\trace_rep.jsonl --model models\qwen2.5-1.5b-instruct-q4_k_m.gguf --model-mb 1111 --instances 4 --budget-pct 60 --concurrency 2 --reps 3 --out results\repeat_cluster.json

# 生成自包含 HTML 仪表盘（浏览器打开 docs\性能仪表盘.html）
python scripts\make_dashboard.py
```

`aggregate_metrics.py` 扫描 `results\` 全部实验 JSON，统一提取九维指标（延迟/吞吐/
内存/IO/命中/负载/SLO/稳定性），生成 `results\metrics_tracking.csv`；
`run_eval_rep.py` 做重复性验证；`make_dashboard.py` 嵌入全部图表与指标表生成仪表盘。

## 9. 常见坑

1. **内存/换出实验必须用本机账户在普通 PowerShell 跑**（沙箱里工作集裁剪/页锁定会被拒绝）；
2. **模型要先下载**（`models\` 不入库，跑实验前先执行 `download_models.ps1`）；
3. 构建脚本已自动处理 CUDA 13.0 残留问题，无需手动设环境变量；
4. 实验数据与图表全部可复现；遇到问题先查本地 `错误自查记录.txt`。
