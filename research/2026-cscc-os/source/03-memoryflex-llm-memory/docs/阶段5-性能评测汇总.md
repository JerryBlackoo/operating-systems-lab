# 阶段 5：性能评测与指标追踪（科学严谨 + 可演示）

日期：2026-08-02　|　引擎：llama.cpp commit `11924d4` + MemoryScheduler/预取补丁
硬件：i9-13900HX / RTX 4050 6GB / 16GB RAM｜模型：Qwen2.5-1.5B/3B、OLMoE-1B-7B（Q4_K_M）

**本阶段不录制视频、不撰写最终答辩材料**；聚焦评测的科学严谨性、指标追踪与可演示性。

## 1. 评测方法学（科学严谨）

### 1.1 指标定义与采集

| 组 | 指标 | 定义/采集 |
|---|---|---|
| 延迟 | TTFT / TPOT（P50/P95/P99） | llama-server 流式响应逐 token 计时（`iter_lines`），排除早期 chunk 合并 bug 数据 |
| 吞吐 | decode tok/s | 解码 token 数 / 解码耗时；与 llama-bench 交叉验证（150 vs 131.8 tok/s 量级一致） |
| 内存 | 峰值/均值 RSS、锁定 MB、KV | psutil 工作集采样；MemoryScheduler `LLAMA_MEM_TRACE` 锁定报告 |
| IO | 缺页次数、预取字节 | psutil `num_page_faults`；补丁 `prefetch_bytes_per_step` |
| 调度 | KV 命中率/命中 token、负载均衡 σ、告警数 | 路由器前缀登记表 + llama-server 实际响应 |
| 质量 | SLO 满足率 | TTFT<500ms、TPOT<250ms 的请求占比（由 detail 数据计算） |
| 稳定性 | RSS 增长、线程数、长跑无崩溃 | 95s 连续请求采样 |

### 1.2 版本锁定与可复现

引擎 commit、补丁（`patches/llama-memory-scheduler.patch`）、模型清单、构建/下载脚本
全部入库（见 [docs/复现与评测指南.md](docs/复现与评测指南.md)）；每次实验 JSON 均保留
配置与结果，`scripts/aggregate_metrics.py` 一键汇总为 `results/metrics_tracking.csv`。

### 1.3 重复性与噪声边界

对集群关键对比（LB vs LMETRIC）重复 3 次（30 请求小样本，`results/repeat_cluster.json`）：

| 策略 | TTFT mean±std | 命中率 | 负载均衡 σ |
|---|---:|---:|---:|
| LB-only | 376.3 ± 11.6 ms | 0.80 | 7.5 |
| LMETRIC | 385.5 ± 8.3 ms | 0.80 | 7.5 |

小样本（30 请求、3 用户）下两者 TTFT 差异落入噪声区间（±3%），**负载均衡 σ 在全部
重复中完全一致（7.5）**——LMETRIC 在不牺牲均衡的前提下是 KV 感知的。在 60 请求、
完整历史的长对话负载下（阶段 4 报告），LMETRIC 相对 LB 的 TTFT 收益为 **−6.2%**、
命中率 +7.6%，收益随会话长度与请求量增大而显现。本报告如实给出该边界，避免小样本
上的过度宣称。

## 4. 诚实边界

- CPU 小模型 + 热缓存：TTFT 噪声 ±3–5%，集群收益在小样本上不显著（已重复验证）；
- MoE 专家预取在本规模净负（机制与边界见阶段 3 报告）；
- 论文级收益（TTFT −92%）对应 GPU 大规模 + 长前缀场景，本项目给出机制验证与
  可放大的边界条件。
