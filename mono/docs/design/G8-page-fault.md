# G8 缺页中断与页面置换

- 王道：3.2 虚拟内存管理（请求分页）
- 汤小丹：第 7 章 虚拟存储（请求分页）

## 实现

- RISC-V `scause=12/13/15` 调用 `vm_handle_fault`；非法地址杀进程。
- 堆区 `[0x40080000, heap_top)` 首次访问分配零页（demand-zero）。
- 常驻堆页上限 `USER_PAGE_LIMIT=48`；demand-zero 分配和换入都受该上限约束，达到上限时按 FIFO 游标驱逐一个已映射堆页。
- 交换区按 `MAX_PROCS × 单进程堆页上限` 配置（当前 16 × 127 个 4 KiB 槽位），覆盖所有进程的堆换出需求；驱逐时复制页面到槽位并解除映射，再次访问时换入；映射成功后才释放槽位，映射失败时保留换出副本。换入时先确认有空闲槽位再预驱逐；槽位全满时先换入目标页并释放其槽位，再按常驻上限驱逐别的页，避免把合法换入误判为非法访问。
- fork 时父进程的换出页以独立 swap 副本交给子进程，不立即物化为常驻页，子进程的 `heap_pages` 仍受 `USER_PAGE_LIMIT` 约束。
- 统计 `page_fault_count`/`evict_count`，用户进程退出时打印 `[vm] faults=... evictions=...`。

## 与教材的对应

- 请求分页：访问才分配；缺页中断负责装入。
- FIFO：最早进入的页先被驱逐；没有实现 Clock/工作集/抖动模型。
- 交换区只在 RAM，不写 SD 卡；不涉及磁盘 I/O。

## 验收

```bash
make && timeout 25s make run
# faulttest: demand paging and swap ok
# [vm] faults=192 evictions=144
```

`faulttest` 通过 `sbrk(96*4096)` 分配 96 页，写入并回读 96 个页首字节；超过 48 个常驻页后触发驱逐和换入。第二轮回读时 FIFO 只有 48 个帧，顺序重扫 96 页会让每页再次缺页：写入阶段缺页 96 次（其中后 48 次各驱逐 1 页），回读阶段缺页 96 次、驱逐 96 次。

## 取舍

- 不做内核页换出、工作集、页面锁、COW 缺页。
- 只驱逐堆页，不驱逐代码/栈。
- ARM 已能跑 `hello/fork/exec/shell`，但未接入用户态缺页；缺页/置换验收在 RISC-V。
