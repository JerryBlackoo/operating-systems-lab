# G5 死锁教学模块（银行家算法）

- 王道：2.4 死锁
- 汤小丹：第 5 章 死锁

## 实现

- `banker_safety_check` 接收 Available/Max/Allocation，现场计算 Need。
- 每次找第一个 Need ≤ Work 的未完成进程，回收其 Allocation，记录安全序列；找不到则返回不安全。
- 自检矩阵采用王道 2.4 的 5 进程 3 资源经典例子：
  - Available = (3,3,2)
  - Max = (7,5,3)、(3,2,2)、(9,0,2)、(2,2,2)、(4,3,3)
  - Allocation = (0,1,0)、(2,0,0)、(3,0,2)、(2,1,1)、(0,0,2)
- 本次实际输出 `P1 P3 P0 P2 P4`；它是合法安全序列之一，和教材示例的次序不要求完全一致。

## 取舍

- 不挂接真实锁，不做运行时死锁检测/恢复；只在启动自检里调用。
- 不实现资源分配图、可视化、银行家算法的动态请求 API。

## 验收

```bash
make && timeout 10s make run
# [banker] safe seq: P1 P3 P0 P2 P4
```

## 已知限制

- 矩阵大小固定 8×4；超出需改宏。
