# init 用户态启动

`init` 用初始能力和一份固定清单启动首批用户程序，并确认每个程序已经就绪。最小模型的输入是预置能力、服务描述和启动器替身，输出是首批服务的启动结果。

## 最小模型

```text
Init = (boot_caps, plan, started, waiting_for, phase)

BOOT ──校验清单与初始能力──> STARTING ──全部确认就绪──> READY
  │                            │
  └──校验失败──> FAILED         └──启动失败 / 提前退出──> 清理 ──> FAILED
```

- `start(service, grants)` 启动清单的下一项，记录子服务引用和本次启动专用的就绪凭据。给子服务的权限取自该项声明的能力子集。
- `ready(receipt)` 核对当前等待项的凭据，登记就绪，再推进清单。启动器返回成功只表示子服务已创建。
- `fail(service, status)` 记录失败项，按启动的逆序停止本轮已创建的服务并释放本轮持有的引用。

## 不变量

1. 清单按给定顺序推进，每项最多启动一次。空清单直接进入 `READY`。
2. 只有当前等待项的就绪确认能推进清单，重复确认只处理一次。
3. `READY` 表示清单中每项都已确认就绪。进入 `FAILED` 时，本轮取得的服务资源已经交还。

## 独立验证

用两个虚拟服务检查依次启动、错序就绪确认和重复确认。让第二项启动失败，观察第一项被回收，再比对启动前后的资源计数。

## QEMU demo

`init.c` 实现清单校验、凭据匹配和逆序清理。启动器替身投递就绪、启动失败和提前退出事件。

```sh
make -C micro/userland/init run
```

从仓库根目录运行，成功时输出 `[init] PASS` 并退出 QEMU。
