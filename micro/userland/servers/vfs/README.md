# vfs 路径与文件描述符

VFS 将路径解析成文件标识，并为每个客户端维护文件描述符和读偏移。最小模型固定一个只读根文件系统，覆盖打开、读取和关闭三步。

## 最小模型

```text
VFS = (root_inode, backend, fd_table)
FD  : (client, fd) ⇀ (inode, offset)

空槽 ──open──> 已打开(offset = 0) ──close──> 空槽
                  └──read 成功──> offset += 实际读取长度
```

- `open(client, path)` 从根按绝对路径的分量调用 `lookup(parent_inode, name)`。前缀分量必须是目录，末项必须是普通文件。成功后分配当前客户端的描述符。
- `read(client, fd, n)` 查得文件和偏移，调用 `read_at(inode, offset, n)`，按返回的字节数推进偏移。到达文件末尾得到空数据。
- `close(client, fd)` 删除描述符记录，交还打开时取得的文件引用。

文件系统替身提供目录项与文件字节。文件系统模块按 inode 与偏移读数据。 [ext4 模块](../fs/ext4/README.md)

## 不变量

1. 描述符由请求上下文中的客户端身份限定。一个客户端的每次成功打开各有一个初始为零的偏移。
2. 路径由非空普通名称组成，逐级查找。成功分配描述符时对应的文件已确定。
3. 短读按实际长度推进，读取失败时偏移取调用开始时的值。关闭后该描述符查询返回无效。

## 独立验证

用内存目录提供 `/demo/hello.txt`，让同一客户端先后打开两次，验证偏移独立。让没有打开文件的客户端使用同一描述符，检查它收到错误。再检查分段读取、短读、EOF 和关闭后的读取。

## QEMU demo

`vfs.c` 实现路径逐级查找和文件描述符操作。内存文件系统替身提供目录及文件内容，并注入一次读错误验证偏移。

```sh
make -C micro/userland/servers/vfs run
```

从仓库根目录运行，成功时输出 `[vfs] PASS` 并退出 QEMU。
