# sm 服务名称注册

服务管理器维护名称到服务端点的绑定。发布者持有注册项，客户端按名称获得自己能力空间内的发送句柄。

## 最小模型

```text
Registry : Name ⇀ (owner, endpoint_ref)

未注册 ──register──> 已注册 ──owner unregister──> 未注册
                       └──lookup──> 发放发送句柄
```

名称是长度有界、区分大小写的非空字节串。注册表有固定容量，句柄发放由能力替身表达。

| 操作 | 契约 |
| --- | --- |
| `register(caller, name, endpoint)` | 检查端点和授权，为有效的新名称保存端点引用 |
| `lookup(caller, name)` | 查到名称后，请能力替身向调用者发放仅具发送权限的句柄 |
| `unregister(caller, name)` | 核对注册者身份，删除名称并释放注册项持有的引用 |

## 不变量

1. 同名最多一条记录。重复注册返回 `EXISTS`。
2. 注册项持有的引用和发给客户端的引用分别计数。注销后查找返回 `NOT_FOUND`。句柄的寿命由持有者和能力表管理。 [capability 模型](../../../kernel/capability/README.md)
3. 句柄按接受方能力空间发放，注册者身份取自请求上下文。发放失败时返回错误，注册项保留原绑定。

## 独立验证

用虚拟端点和两张能力表验证注册、查找和注销。检查重复注册、越权注销和客户端能力槽位耗尽，确认端点引用计数与有效绑定和句柄一致。

## QEMU demo

`sm.c` 实现名称表。能力替身在两个客户端的槽位中分别发放发送句柄，并追踪端点引用。

```sh
make -C micro/userland/servers/sm run
```

从仓库根目录运行，成功时输出 `[sm] PASS` 并退出 QEMU。
